# 污染源在线监测与排污总量核算台

运维与环保岗共用的核算台：录排污单位与排放口、管在线设备、盯小时值、算日平均与总量、对许可量、出报表。

## 运行

```
npm install
npm start
```

默认端口 5261（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：单位数量与生产中数量、排放口数量与运行中数量、设备数量与各状态台数、监测数据条数与自动与补录条数、无效标记条数、报表数量与已上报数量、超标排放口数量、年累计排放量与年许可量对照；下面按排放口一行给出本月各指标的月均值、月总量与超标情况。
- **排污单位与排放口**：单位台账（编码、名称、行业、状态、许可证号、许可年起始日）带排放口清单；排放口台账（编码、名称、所属单位、类型、状态、设备数、数据条数），两者都带增改删。
- **在线设备**：设备台账（编号、所属排放口、监测指标、型号、设备状态、校准有效期、数据条数、无效标记条数），带增改删。
- **监测数据**：小时值清单（排放口、设备、指标、时刻、数值、标记、来源、登记人、是否计入、折算后浓度、当时氧含量与流量），支持按排放口、设备、指标、日期与月份筛选，带单条新增、修改与删除。
- **核算与报表**：选定排放口与月份后给出逐日明细（有效小时数、补录小时数、日均浓度、限值、是否超标、当日流量合计）与汇总（月均、月总量、季度总量、季度许可量、年累计、年许可量、超标天数与超标小时数、超标判定），并可生成与查看报表（草稿、已上报、退回）；已上报月份按当时适用许可版本冻结核算快照，可在详情里「按当前数据试算对比」。
- **许可变更**：按排污单位登记许可量分段（变更生效日、变更后 COD/氨氮年许可量、依据文件、登记人、登记时刻）；时间线展示系统默认段与各次变更；许可年逐月台账给出分段构成、按日折算月许可、实测月已用、年累计许可/已用、剩余（亏空标红）与冻结标记，点月份可展开逐段的「年许可 / 天数折算许可 / 实测已用 / 段内剩余」。

## 口径（页面上的说明与数字都要与本段一致）

1. **有效小时值**：数据标记为有效、设备状态为「正常」、数值在量程（默认 0 到 500）之内，三条都满足才计入统计；设备处于校准、维护、故障状态，或者数值超量程或为负数的，按无效处理（不计入平均、总量与超标判定），页面要显式标出来。
2. **折算浓度**：`折算浓度 = 实测浓度 × (21 − 基准氧含量) / (21 − 实测氧含量)`，基准氧含量默认 8（可在设置里改）；该时刻没有氧含量读数时按基准氧处理（等价于不折算）。所有平均、总量与超标判定都用折算后的浓度。
3. **日平均**：按小时流量加权，`日均 = Σ(折算浓度 × 该小时流量) / Σ该小时流量`；单日有效小时不足（口径按 18 小时）或者补录小时超过上限（默认 6 小时）的，**该日不计入平均与总量**，页面要写明原因。
4. **补录**：允许用相邻有效值补算缺失小时，补录数据要在页面与结果里与原数据区分开；补录超过单日上限时该日按无效处理，不许把补出来的数当真实监测结果用。
5. **月总量**：`每小时排放量(吨) = 折算浓度(mg/L) × 流量(m³/h) × 1000(升每立方米) / 1e9`，月总量是逐小时按时刻配对累加（浓度与流量必须取同一时刻的那一对）；月平均按有数据且有效的天数平均（分母是有效天数，不是当月天数）。季度总量与年累计用同一套公式逐小时累加，不做任何按天外推。
6. **许可年与按日折算**：年累计按许可年（单位台账里的许可年起始日）累计，跨许可年自动分年。某时段的许可量一律按日折算：`时段许可量 = 年许可量 × 时段天数 / 该历年天数（闰年 366）`；季度许可量同理按季度实际天数折算。
7. **许可分段（变更登记）**：许可量按排污单位一企一证分段，每段登记变更生效日、变更后 COD/氨氮年许可量、依据文件、登记人（登记时刻由系统生成）。某日适用的许可 = 生效日不晚于该日的最近一次登记；**变更生效日当天归新版**。没有登记过任何变更的单位/时段，用「设置」里的年许可量作为系统默认段兜底。允许补登历史生效日，但同一单位同一生效日不得重复登记。
8. **变更当月的核算**：月内发生变更的月份按日切分到各段，每段许可量按第 6 条折算，实测已用量按小时读数（同刻配对流量）实际落到的日期归集；两段相加得到当月许可量与已用量。变更时刻之前已经核算的月份始终用当时适用的版本重算口径不变，台账可展开查看每月用的是哪一版许可（系统默认或版本号 + 依据文件）。
9. **年內衔接与剩余量**：同一许可年内变更不重置指标——年累计已用按小时实测逐段相加，年累计许可 = 上年带入 + 截至月末各段按日折算许可之和，`剩余 = 年累计许可 − 年累计已用`（负数即超支，红色显示）。
10. **跨年变更与余额结转**：当一次变更新开一个许可年时，逐指标登记上年余额的处理：`不结转`（0）、`上年结余全额结转`（系统自动按上一许可年末「折算许可 + 上年带入 − 实测已用」计算余额，亏空不结转、钳为 0）、`指定结余量`（手工填吨数，非负）；该带入量对整个新许可年有效。许可年内的变更不登记结转。
11. **已上报冻结**：月报进入「已上报」时（新建即上报或状态改上报），系统按当前数据生成不可改写的快照：各排放口月总量、单位分指标合计、当月分段折算（版本号/生效日/依据/天数/许可/已用）、年累计许可与已用、上年带入、剩余与结论，以及冻结时刻、上报人、版本号。之后许可再变更或监测数据补录，已上报月份仍展示冻结快照；月报退回后重新上报会追加新快照（序号递增，历史保留）。需要核对可在月报详情「按当前数据试算对比」。被任一已上报快照引用过的许可版本，数值禁止修改或删除（`VERSION_FROZEN`）；已上报月报只允许改备注或退回（`REPORT_LOCKED`）。
12. **超标判定**：日平均超过限值（COD 100、氨氮 15，可改）**或者**小时值超过限值达到 3 次及以上，都算这个月超标；两项都要在页面上分别给出。
13. **不计入统计的情形**：排污单位处于停产状态、或者排放口处于停用状态的时段，其小时值不计入平均与总量，也不参与超标判定（但要保留可查）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/plants | 单位清单（支持 status、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/plants/:id | 详情（含排放口、报表）/ 修改 / 删除 |
| GET / POST | /api/outlets | 排放口清单（支持 plantId、status）/ 新增 |
| PATCH / DELETE | /api/outlets/:id | 修改 / 删除 |
| GET | /api/outlets/:id/summary?month= | 月均、月总量、季度总量与许可、年累计、超标情况、设备清单 |
| GET | /api/outlets/:id/daily?month=&metric= | 逐日明细（有效小时数、补录小时数、日均、限值、是否超标、流量合计） |
| GET | /api/outlets/:id/exceedance?month=&metric= | 超标判定（超标天数、超标小时数、是否超标、月均） |
| GET / POST | /api/devices | 设备清单（支持 outletId、metric、status）/ 新增 |
| PATCH / DELETE | /api/devices/:id | 修改 / 删除 |
| GET / POST | /api/readings | 小时值清单（支持 outletId、deviceId、metric、day、month、limit）/ 新增 |
| PATCH / DELETE | /api/readings/:id | 修改 / 删除 |
| GET / POST | /api/reports | 报表清单（含 frozen、snapshotCount，不带快照正文）/ 新建（状态直接给已上报时立即冻结，需上报人） |
| GET / PATCH | /api/reports/:id?compare= | 报表详情：有快照时带 frozen、snapshot（最近一次）、snapshotHistory；compare=1 额外给 live 当前试算 / 改状态（转已上报即冻结，已上报只许改备注或退回） |
| GET | /api/reports/:id/snapshots | 该报表全部历史冻结快照 |
| GET / POST | /api/permit-versions?plantId= | 许可分段清单（frozen、boundary、isLatest、结转标签）/ 登记变更（跨年开户段带 carryover） |
| PATCH / DELETE | /api/permit-versions/:id | 修改未冻结版本数值（生效日等不可改）/ 删除（只许删最后一条且未冻结） |
| GET | /api/plants/:id/permit | 单位许可详情（版本时间线 + 系统默认段） |
| GET | /api/plants/:id/ledger?from=&to= | 许可年逐月台账（分段折算、月/年累计许可与已用、剩余、当月冻结记录） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。分段相关错误码：`VERSION_DATE_CONFLICT`（同日重复登记，409）、`VERSION_FROZEN`（版本被快照引用，409）、`VERSION_HAS_SUCCESSOR`（中间版本不可删，409）、`REPORT_LOCKED`（已上报月报锁定，409）、`REPORT_DUPLICATE_PERIOD`（同单位同期间重复，409）。
